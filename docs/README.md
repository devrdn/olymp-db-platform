# Documentation

Where to read what. If you are new, read the developer guide in order; the
rest is reference you will come back to.

## The developer guide

A path through the project for your first days on it.

| Chapter | What it gives you |
|---|---|
| [1. Overview](guide/01-overview.md) | The product, who uses it, the domain vocabulary, the system at a glance and a tour of the repository |
| [2. Use cases](guide/02-use-cases.md) | Every actor, what each can do, and the screen, endpoint, package and permission behind each action |
| [3. Flows](guide/03-flows.md) | Sequence diagrams of the flows that matter: a request through the stack, sign-in, a query, an answer, the contest lifecycle |
| [4. Backend](guide/04-backend.md) | How the Go code is organised, the anatomy of a domain package, and recipes for an endpoint, a package, a migration, an error code, a permission |
| [5. Frontend](guide/05-frontend.md) | Route groups, how a page gets its data, UI text and locales, the play screen, and recipes for a page, an API module, a string |
| [6. Testing](guide/06-testing.md) | The kinds of tests, how to run each, what CI runs, and how to write a good one here |
