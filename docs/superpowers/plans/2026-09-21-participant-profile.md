# Профиль участника — план

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** участник видит в профиле свои олимпиады, а по каждой законченной —
отчёт, свои запросы, ответы и заметки. Чужого — ничего, во время олимпиады —
только ссылка в неё.

**Дизайн (источник требований):** `docs/superpowers/specs/2026-09-21-participant-profile-design.md`.
Каждая задача читает его целиком перед началом.

## Что уже есть и на чём это стоит

- **Чтения, которые нужно переиспользовать:** `backend/internal/monitor`
  (`WatchService.Participant/Queries/Answers/Workspace`, типы страниц и
  курсоров) и `backend/internal/postgres/watch*.go`. Они уже принимают пару
  «олимпиада — регистрация» и проверены на планы запросов
  (`TestWatchReadsScanNoJournal`).
- **Счёт результата:** `backend/internal/leaderboard` (`Decide`, `Rank`,
  `RankICPC`, `Service` с кэшем) — единственный источник баллов, решённых,
  штрафа, места и того, открыта ли таблица.
- **Доступ участника:** `backend/internal/queryproxy` (`Access`, `AdmitRead`),
  `contests.Deadline`, статусы регистрации.
- **CSV потоком:** `queryLogCSV` в `backend/internal/api/participant_handler.go`
  с пределами по строкам, байтам и времени.
- **Экран профиля:** `frontend/app/(session)/profile/page.tsx` (шапка, поля,
  выход), `components/ui/avatar` + `lib/format/initials`.
- **Список олимпиад участника:** `frontend/app/(participant)/my/` —
  `participant-register.tsx` (строки олимпиад, кнопка входа).
- **Готовые части экрана наблюдения для переиспользования:**
  `frontend/app/(admin)/contests/[contestId]/monitor/` — список запросов с
  подсветкой и копированием, ответы с ведущими запросами, вкладки в адресе.
  Общее выносить в `components/product/`, а не копировать.
- **Словари:** `frontend/lib/i18n/dictionaries/{en,ru,ro}.ts`.
  Проверки: `npm run error-codes`, `make api-contract`, `make front-check`.
- Последняя миграция — `000033_participant_monitoring`. **Новых таблиц не
  нужно.**

## Global Constraints

- `CLAUDE.md` обязателен целиком, особенно:
  - правило 1 (отказ — объявленный сентинел, маппинг в `fail`, тест
    обработчика, код в `docs/api/error-codes.json`, тексты en/ru/ro);
  - правило 2 (явные пределы у каждого поля и списка);
  - правило 3 (`escapeLike` для поиска);
  - правило 5 и правило 13 (ограничитель до дорогой работы, отказы считаются);
  - правило 6 (запись на запрос — только по делу);
  - правило 7 (фильтр опирается на индекс);
  - правило 10 (гарантия доказывается на пути развёртывания);
  - раскладка Go;
  - английский в коде и коммитах, русский в `docs/`;
  - линейная история.
- **Только своё:** регистрация берётся из сессии, id регистрации в URL нет.
  Незакончившаяся для участника олимпиада и чужая — один и тот же 404.
- **Заморозка не обходится:** место и число участников показываются, только
  когда `leaderboard.Decide` говорит, что таблица открыта.
- **Ни одной второй формулы:** баллы, решённые, штраф и место считает
  `leaderboard`; запросы, ответы и рабочее место читает `monitor`.
- Реальные данные не трогать: только тестовая база и `pg-game-test`. Никаких
  `make run`, `make runner`, `make dev-*` и docker-команд.
  `deploy/.env` не редактировать. `.superpowers/` не коммитить.
- Каждое изменение начинается с теста. Коммиты небольшие; в индекс добавлять
  файлы явно по путям.

## Task 1: API «своё»

Спека: разделы 3 и 4.

- Маршруты `/me/summary`, `/me/contests`, `/me/contests/{contestId}/report`,
  `/queries`, `/answers`, `/workspace`, `/log.csv` в новом файле пакета `api`.
- Общий допуск: регистрация по `user_id` из сессии, олимпиада закончена для
  этого участника (окончание, индивидуальный дедлайн, дисквалификация), иначе
  404 тем же кодом; бюджет чтения на учётную запись до работы с базой.
- Отчёт и строки списка считаются через `leaderboard` и `monitor`; место — по
  `Decide`. Ошибки запросов — через `participantSafeError`.
- `/me/contests` — один агрегирующий запрос по регистрациям участника
  (не по запросу на олимпиаду).
- Коды, тексты en/ru/ro, Postman, `make api-contract`.
- Тесты: обработчики (каждый отказ и каждое правило), репозиторий под
  `make test-db` (список и отчёт на данных, где рядом лежат чужие
  регистрации), совпадение отчёта с лидербордом.

## Task 2: экран профиля

Спека: разделы 2.1 и 5.

- `/profile`: шапка, сводка четырьмя числами, список олимпиад со своим
  результатом и кнопкой входа у идущей, пустое состояние.
- Внешний вид по SPEC: без коробок, линейки, инициалы, моноширинные числа.
- Тесты vitest: список, пустое состояние, идущая олимпиада (только ссылка),
  скрытое место при заморозке.

## Task 3: экран отчёта по олимпиаде

Спека: раздел 2.2.

- `/profile/contests/[contestId]` с вкладками в адресе: «Итог», «Мои
  запросы», «Мои ответы», «Мои заметки», кнопка CSV.
- Общие части с экраном наблюдения вынести в `components/product/`
  (список запросов, ответы с ведущими запросами), не копировать; тесты
  наблюдения остаются зелёными.
- 404 для идущей и чужой олимпиады.
- Тесты vitest на каждую вкладку и на 404.
