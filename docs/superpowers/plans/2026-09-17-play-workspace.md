# Рабочее место участника — план

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** заметки и вкладки SQL, которые сохраняются сами и переживают
перезагрузку; полный просмотр записи журнала запросов; сворачиваемые панели
экрана `/play`.

**Дизайн (источник требований):** `docs/superpowers/specs/2026-09-17-play-workspace-design.md`.
Каждая задача читает его целиком перед началом.

## Что уже есть и на чём это стоит

- Маршруты участника: `backend/internal/api/participant_handler.go`
  (`Mount`, `admit`, `queryLog`). Доступ: `queryproxy.Service.Access` и
  `AdmitRead`. Журнал: `backend/internal/queryrunner/history.go`
  (`HistoryEntry`, `MaxHistorySQLChars = 1000`) и
  `backend/internal/postgres/querylog.go`.
- Предел запроса: `sqlpolicy.MaxQueryBytes` (64 КиБ).
  Ограничитель частоты: `auth.Limiter` (кэш).
  Защита от чужого Origin: `httpx.CheckOrigin`.
- Последняя миграция — `000031_icpc_scoring`, новая — `000032_play_workspace`.
- Экран: `frontend/app/(participant)/contests/[contestId]/play/`:
  - `workspace.tsx` — сетка из трёх колонок; нижняя панель с долями 11:9;
  - `pane-splitter.tsx` — `PaneHandle` и `usePaneWidths` с `localStorage`;
  - `console.tsx` — `ConsoleEditor`: форма, скрытый textarea и server action `runQueryAction`;
  - `side-panel.tsx` — вкладки «История», «Вопросы», «Таблица»;
  - `query-log-panel.tsx`;
  - `play-header.tsx`;
  - `actions.ts` — server actions.
- Редактор: `frontend/components/product/code-editor.tsx` и
  `code-editor-core.ts` (CodeMirror 6, неуправляемый документ).
- Браузер ходит в API напрямую через `API_PREFIX = "/api/v1"`
  (`frontend/lib/api/client.ts`), как ссылка на CSV журнала.
- Словари: `frontend/lib/i18n/dictionaries/{en,ru,ro}.ts`.
  Проверки: `npm run error-codes`, `make api-contract`, `make front-check`.

## Global Constraints

- `CLAUDE.md` обязателен целиком, особенно:
  - правило 1: отказ — объявленный сентинел, сопоставленный в `fail`, с тестом обработчика, кодом в `docs/api/error-codes.json` и текстами en/ru/ro;
  - правило 2: явные пределы;
  - правило 6: запись на запрос — только по делу;
  - правило 9: ключи ограничителя — только через `httpx`;
  - правило 10;
  - правило 13: ограничивать частоту до дорогого шага и считать отказы;
  - раскладка Go: файлы называются по содержимому, тесты зеркалят файлы, интерфейсы объявляет потребитель;
  - правило 3: английский в коде, комментариях и коммитах; проза в `docs/` — на русском;
  - правило 4: история линейная.
- Числа из спеки брать дословно:
  - 20 000 символов заметок;
  - 10 вкладок;
  - название 1–40 символов;
  - текст вкладки ≤ `sqlpolicy.MaxQueryBytes`;
  - 60 записей в минуту на учётную запись участника, отказы считаются;
  - задержка сохранения 1,5 с, максимум 10 с;
  - повтор 2→30 с.
- Экран остаётся быстрым: при наборе текста React не перерисовывает дерево
  (контракт `CodeEditor.onChange`); крупные панели остаются в `memo`.
- Реальные данные не трогать: только `dbcontest_core_test` и `pg-game-test`.
  Никаких `make run`, `make runner`, `make dev-down` и docker-команд, которые
  останавливают или удаляют контейнеры. `deploy/.env` не редактировать.
- Каждое изменение начинается с теста. Коммиты небольшие; в индекс добавлять
  файлы явно по путям.

## Task 1: хранилище рабочего места на сервере

Спека: разделы 1, 3, 4.

- Миграция `000032_play_workspace`, up и down, как в спеке.
- Доменный пакет `backend/internal/workspace`. Он отвечает на вопрос «заметки и
  вкладки одного участника олимпиады»:
  - типы и пределы;
  - сервис с сентинелами `ErrNotesTooLong`, `ErrTooManyTabs`, `ErrTitleInvalid`,
    `ErrTabBodyTooLong`, `ErrTabNotFound`, `ErrLastTab`, `ErrOrderMismatch`,
    `ErrTooOften`;
  - ограничитель частоты по учётной записи (`AdmitWrite`, до поиска участника):
    60 в минуту, отказы тоже считаются;
  - создание первой вкладки при первом чтении, с названием на языке запроса.

  Репозиторий — в `backend/internal/postgres/workspace.go`, интерфейс объявляет
  потребитель. Позиции вкладок назначаются и переупорядочиваются в одной
  транзакции.
- Обработчики в `ParticipantHandler` (или в отдельном файле того же пакета
  `api`, по образцу):
  - `GET /play/workspace`;
  - `PUT /play/notes`;
  - `POST /play/tabs`;
  - `PATCH /play/tabs/{tabId}`;
  - `DELETE /play/tabs/{tabId}`;
  - `PUT /play/tabs/order`.

  Все проходят через `Access`, как остальные маршруты `/play`: после окончания
  олимпиады чтение и запись отвечают `contest_not_running` или
  `contest_finished`, режима «только чтение» нет. Запись не тратит бюджет
  чтения (`AdmitRead`), а тратит свой (`AdmitWrite`).
  Коды ошибок из спеки, 409/429/404/400, тексты en/ru/ro, `make api-contract`,
  Postman-коллекция.
- Тесты: сервис (каждый предел и его граница, частота с учётом отказов,
  последняя вкладка, несовпадение порядка, первая вкладка),
  репозиторий под `make test-db` (каскадное удаление с регистрацией, чужая
  вкладка не видна и не меняется), обработчики (каждый код).

## Task 2: полная запись журнала

Спека: раздел 7 (серверная часть).

- В ответ `GET /play/log` добавить `id` каждой записи (uuid из `query_log`).
- Новый маршрут `GET /play/log/{entryId}`. Возвращает одну запись этого
  участника с полным текстом (не обрезанным, не больше `MaxQueryBytes`) и
  ошибкой в том же виде, в каком её отдаёт `participantSafeError`. Чужая или
  несуществующая запись — 404 с кодом, без различия между случаями.
  Некорректный id — 400.
- Тесты: репозиторий (чужая запись недоступна), обработчик, контракт API,
  Postman.

## Task 3: автосохранение и заметки

Спека: разделы 1, 2, 6.

- `frontend/lib/api/workspace.ts`: zod-схемы и функции браузера для записи
  через `API_PREFIX` (`credentials: "same-origin"`, `keepalive` для отправки на
  `pagehide`). Первичное чтение идёт на сервере в `page.tsx` параллельно с
  остальными запросами; ошибка чтения не ломает экран (заметки показывают
  «не удалось загрузить», редактор — одну локальную вкладку).
- Хук `use-autosave.ts` рядом с экраном, со всем поведением из спеки: задержка
  и максимальное ожидание, без дублей, один запрос в полёте, повтор с
  нарастающей паузой, 429 — отложить, 409 `contest_not_running` или
  `contest_finished` — остановить автосохранение, оставить черновик и сообщить,
  что олимпиада завершена,
  черновик в `localStorage` (устойчивый к исключениям хранилища), немедленная
  отправка на `visibilitychange` и `pagehide`, а также при `flush()`. Статус
  возвращается наружу.
- Вкладка «Заметки» в `side-panel.tsx`: поле, статус, счётчик от 18 000,
  сообщение о завершении олимпиады при отказе записи, тексты en/ru/ro.
- Тесты vitest с поддельными таймерами на всё поведение хука и на вкладку.

## Task 4: вкладки SQL-редактора

Спека: раздел 5.

- Полоса вкладок над редактором:
  - создание, закрытие с подтверждением, если текст не пустой;
  - переименование двойным щелчком или F2 (Enter — сохранить, Esc — отменить);
  - перетаскивание и `PUT /play/tabs/order`;
  - роль `tablist` и стрелки;
  - предел 10 (кнопка «+» недоступна и объясняет почему);
  - при отказе записи из-за окончания олимпиады — автосохранение
    останавливается, черновик остаётся, показывается, что олимпиада завершена.
- `CodeEditor` умеет переключать документ: для каждой вкладки хранится свой
  `EditorState` с отдельной историей и курсором. React при наборе по-прежнему
  не перерисовывает дерево.
- Текст каждой вкладки сохраняется через `useAutosave`. Активная вкладка
  хранится в `localStorage`. Запуск берёт текст активной вкладки. Заголовок
  результата называет вкладку.
- Тесты vitest: полоса вкладок, переименование, закрытие, предел, запуск
  активной вкладки, восстановление после перезагрузки (черновик новее
  серверного текста).

## Task 5: раскрытие строки результата и вертикальные разделители

Спека: раздел 7.

- Строки таблицы результата выбираются щелчком и Enter, фокусируются с
  клавиатуры. Панель подробностей под таблицей:
  - все колонки выбранной строки с полными значениями, перенос длинных,
    `NULL` как в таблице;
  - «Копировать значение», «Копировать строку», «Закрыть» и Esc;
  - стрелки вверх и вниз переходят к соседней строке;
  - новый запуск запроса закрывает панель.
  Таблица виртуализирована (`ResultTable`), поэтому выбор хранится по номеру
  строки, а не по узлу DOM.
- Журнал запросов не трогаем: там раскрытия строк нет.
- Вертикальный разделитель между таблицей и панелью подробностей, и такой же
  между редактором и нижней панелью. Перетаскиваются мышью и стрелками,
  высоты запоминаются, как `usePaneWidths` (обобщить, а не копировать).
- Тесты vitest.

## Task 6: сворачиваемые панели

Спека: раздел 8.

- Переключатели в шапке экрана, сочетания Ctrl/⌘+B, Ctrl/⌘+Alt+B и Ctrl/⌘+J
  (в том числе из редактора CodeMirror), состояние в `localStorage` по
  олимпиаде.
- Сетка убирает свёрнутые колонки и разделители. Нижняя панель раскрывается
  сама после выполнения запроса. На узком экране панели тоже прячутся.
- Тесты vitest. Проверка в браузере на 1440, 1024, 768 и 375 px со
  скриншотами в отчёте.
