# Режим оценки ICPC — план

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** третий режим оценки олимпиады, `icpc`: место решают число решённых
вопросов и штрафное время; таблица показывает сетку вопросов и, при заморозке,
«ожидающие» попытки.

**Дизайн (источник требований):** `docs/superpowers/specs/2026-09-13-icpc-scoring-design.md`.
Каждая задача читает его целиком перед началом.

## Что уже есть и на чём это стоит

- Режимы `points` и `winner`: `backend/internal/contests/contests.go`
  (`ScoringPoints`, `ScoringWinner`, `Validate`), запрет смены во время
  олимпиады — `checkRunningChange` в `service.go`, штраф — `penaltyAmount` в
  `submission.go`, гейт — `publish.go`.
- Лидерборд целиком: пакет `backend/internal/leaderboard` (`Decide`, `Rank`,
  `Service` с кэшем), репозиторий `backend/internal/postgres/leaderboard.go`
  (один агрегирующий SQL с отсечкой `submitted_at < cutoff` и
  `registrations.created_at < cutoff`), обработчик
  `backend/internal/api/leaderboard_handler.go`. Дизайн лидерборда —
  `docs/superpowers/specs/2026-09-13-leaderboard-design.md`.
- Последняя миграция — `000030_leaderboard`. Новая — `000031_icpc_scoring`.
- Фронт: `frontend/components/product/standings.tsx` (таблица, медали,
  цвета участников), `frontend/lib/api/leaderboard.ts` (zod-схемы),
  `frontend/app/(admin)/contests/[contestId]/standings/staff-standings.tsx`,
  палитра — `frontend/styles/tokens.css` и `docs/design/SPEC.md` раздел 3.5,
  проверка контраста — `frontend/scripts/contrast.mjs`.

## Global Constraints

- `CLAUDE.md` целиком. В частности: правило 1 — каждый отказ до HTTP —
  объявленный сентинел с отображением и тестом на 4xx; правило 2 — у каждого
  поля явная граница; правило 7 — фильтр опирается на индекс; правило 9 —
  адрес только через `httpx.ClientIP`; правило 3 — коммиты, комментарии и имена
  по-английски, `docs/` по-русски; правило 4 — история линейная, никаких merge.
- Значения, использовать дословно:
  - режим: `icpc`; колонка `contests.icpc_penalty_min smallint NOT NULL DEFAULT 20`,
    `CHECK (icpc_penalty_min BETWEEN 0 AND 240)`;
  - JSON-поле олимпиады и сводки: `icpc_penalty_min` (целое), в сводке ещё `scoring`;
  - отказ гейта: `icpc_choice_needs_attempt_limit`;
  - состояния клетки: `solved`, `failed`, `pending`, `untried`;
  - поля строки ответа таблицы в ICPC: `penalty` (минуты, целое), `cells`;
    поле ответа: `questions` (массив букв `"A"`, `"B"`, …).
- Правило заморозки из дизайна лидерборда сохраняется для `points` и `winner`
  без исключений. Для `icpc` после заморозки уходит **только** число попыток
  в `[freeze_at, now)` по вопросам, не решённым до заморозки — ни верность, ни
  минуты, ни изменения «решено» и штрафа, ни регистрации после заморозки.
  Любой тест, который проверяет утечку, проверяет **тело ответа**.
- Минута решения — `floor` от секунд между стартом и первым верным ответом,
  делённых на 60. Старт: `contests.starts_at` при `timing = fixed`,
  `registrations.started_at` при `timing = individual`.
- Скрытые вопросы не участвуют ни в расчёте, ни в сетке. Вопрос в ответе
  называется буквой по позиции среди видимых, в порядке `ord`, никогда
  идентификатором.
- Тесты: без testify; тест зеркалит исходный файл; SQL проверяется на
  `make test-db` (тестовая база, никогда рабочая). `make test-game` не нужен.
- Контракты после новых кодов: `make api-contract`; тексты кодов — во всех
  трёх словарях (`npm run error-codes` проверяет).
- Цвет только токенами; каждая новая пара «текст на фоне» — в
  `frontend/scripts/contrast.mjs`; без фиолетового, эмодзи, свечений, градиентов.

## Task 1: режим и штраф в олимпиаде, нулевые баллы, отказ гейта

Бэкенд целиком для настройки режима, без таблицы.

- Миграция `000031_icpc_scoring` (up и down): расширить `CHECK` колонки
  `contests.scoring` до `('points', 'winner', 'icpc')` (ограничение сейчас
  называется `contests_scoring_check`), добавить `icpc_penalty_min` со
  значениями из Global Constraints.
- Домен `contests`: константа `ScoringICPC = "icpc"`, поле
  `Contest.ICPCPenaltyMin int`, `Validate` принимает режим и держит границы
  0…240, `checkRunningChange` отказывает при смене штрафа во время олимпиады
  (смена режима уже запрещена), `auditFields` пишет `icpc_penalty_min`,
  `CreateCommand` (умолчание 20) и `UpdateCommand` (указатель: nil — не менять).
  Тестовое хранилище `conteststest` ставит умолчание 20 так же, как ставит
  умолчание подписи лидерборда.
- Баллы: в режиме `icpc` ответ записывает `points_awarded = 0` и не увеличивает
  `total_score` (сейчас `penaltyAmount` и `Submit` передают `q.Points`).
  Тест в `submission_test.go`: верный ответ в ICPC-режиме даёт 0 баллов.
- Гейт `publish.go`: `ProblemICPCChoiceNeedsAttemptLimit =
  "icpc_choice_needs_attempt_limit"` — в режиме `icpc` у вопроса вида `choice`
  нет `max_attempts` или `max_attempts >= len(choice_ids)`. Отказ с
  `QuestionID`. Тесты: отказ без лимита, отказ при лимите равном числу
  вариантов, принятие при лимите меньше; в режиме `points` не срабатывает.
- Репозиторий `postgres/contests.go`: читать и писать колонку во всех
  проекциях и `Create`/`Update` (список контестов сканируется отдельно —
  не пропустить). Тест круговой записи в `contests_test.go`.
- API `contests_handler.go`: `icpc_penalty_min` в `ContestResponse` и в
  `contestRequest` (указатель), `scoring` и `icpc_penalty_min` в
  `ContestSummary`; `contest_package.go` переносит штраф. Тест круговой
  записи через API.
- `cmd/consoleload/fixture.go` создаёт олимпиаду напрямую в репозитории —
  проверь, что ему хватает умолчаний, или задай поле явно.
- Проверки: `go test ./...`, `make test-db`, `make api-contract` не нужен
  (новых HTTP-кодов нет), `gofmt`, `go vet`.

## Task 2: ICPC-таблица на сервере

Расчёт, клетки, «ожидающие», ответ API. Прочитай дизайн лидерборда и его код
до начала: ICPC встраивается в тот же `Service`, тот же кэш, те же состояния и
отсечки, а не рядом.

- **Репозиторий** (`postgres/leaderboard.go`): для `icpc` — отдельный запрос
  или ветка, возвращающая по регистрации: число решённых, штрафное время в
  минутах, момент последнего решения и клетки по видимым вопросам в порядке
  `ord`. Для клетки нужны: момент первого верного ответа до отсечки, номер
  попытки этого ответа, число неверных до него, число неверных до отсечки для
  нерешённого, и — только когда передан момент заморозки — число попыток в
  `[freeze_at, now)`. Штраф `icpc_penalty_min` и старт (по `timing`) берутся
  из олимпиады в самом запросе. Оконные функции допустимы. Порядок и `LIMIT` —
  как у ранжирования (решено ↓, штраф ↑, последнее решение ↑, id), чтобы
  обрезка списка не резала верх. Индекс `submissions_registration_submitted_idx`
  уже есть; если план запроса требует ещё индекс для чтения по вопросам
  олимпиады — добавь миграцией в этой же задаче и обоснуй в отчёте.
- **Домен** (`leaderboard`): расширить `Entry` и `Row` полями ICPC (штраф,
  последнее решение, клетки), `Rank` получает ветку `icpc` (общие места при
  равных «решено» и штрафе), `Query` получает момент заморозки для
  «ожидающих». Отметка «первый решивший» по вопросу — в домене по уже
  отсечённым данным среди строк без дисквалифицированных. `Service.Public` и
  `ForParticipant` передают заморозку только в состоянии `frozen`;
  `Service.Live` не передаёт никогда.
- **API** (`leaderboard_handler.go`): для `icpc` — поле `questions`, у строки
  `penalty` и `cells` (у клетки: `state`, `attempts`, `minute`, `first`,
  `pending` — ровно те, что имеют смысл в её состоянии). Для `points` и
  `winner` ответ байт в байт прежний. Живая таблица организатора — те же поля.
- **Тесты, обязательные:** минута округляется вниз (59 с → 0, 60 с → 1);
  старт при индивидуальном таймере — `started_at`; неверные после верного и по
  нерешённому вопросу не штрафуют; равные «решено» и штраф — общее место;
  скрытый вопрос не в сетке; первый решивший не учитывает
  дисквалифицированного; **при заморозке**: попытка после заморозки даёт
  `pending` с числом, но тело ответа не содержит ни минуты, ни `solved`, ни
  изменения «решено» и штрафа для этого вопроса (в том числе когда попытка
  была верной); первый решивший не ставится по ответу после заморозки; живая
  таблица организатора видит решение и не содержит `pending`; ответ `points`
  не изменился. Сломай отсечку `pending` в коде и убедись, что тест тела
  ответа падает — опиши это в отчёте.
- Проверки: `go test -race ./internal/leaderboard ./internal/api`,
  `make test-db`, `go vet`, `make sec`.

## Task 3: настройки, редактор вопроса, экран игры, участники

Фронт вокруг режима, без таблицы.

- `frontend/lib/api/contests-terms.ts`: `SCORINGS` получает `icpc`.
  Схемы олимпиады и сводки (`lib/api/contests.ts`) читают `icpc_penalty_min` и
  (в сводке) `scoring`.
- Словари `en`, `ru`, `ro`: название режима «ICPC», подсказка режима,
  подпись поля штрафа («Штраф за неверную попытку, минуты»), подсказка, фраза
  редактора «не используются в режиме ICPC», строка экрана игры «+{n} мин за
  неверную попытку по решённому вопросу», вердикт верного ответа без баллов,
  текст отказа гейта `icpc_choice_needs_attempt_limit` (и константа в
  `lib/api/publish-gate.ts`).
- Настройки олимпиады (`settings-panels.tsx`, `settings/actions.ts`): режим
  ICPC в выборе режима; поле штрафа видно только при `icpc`, заблокировано
  вместе с формой олимпиады после старта, отправляется только когда поле не
  заблокировано.
- Редактор вопроса (`questions/[questionId]/question-editor.tsx` и его
  `page.tsx`): в режиме `icpc` поля баллов и процентного штрафа неактивны,
  рядом фраза. Значения не стираются.
- Экран игры (`play/questions-panel.tsx` и то, что ему передаёт режим — через
  сводку олимпиады, которую `play/page.tsx` уже читает): в `icpc` не
  показывать баллы вопроса, показать строку штрафа, вердикт без баллов.
- Участники в админке (`people/people-panels.tsx`): в `icpc` колонку суммы
  баллов не показывать.
- Тесты компонентов на каждое из этого; `npx tsc --noEmit`, `npm run lint`,
  `npm test`, `npm run error-codes`.

## Task 4: ICPC-таблица на экране

- Схемы `lib/api/leaderboard.ts` читают `questions`, `penalty`, `cells`
  (публичная, участника и организатора).
- `components/product/standings.tsx`: для `icpc` колонки «место, участник,
  решено, штраф»; на варианте `page` и на ширине от `narrow` — сетка по
  буквам вопросов; на `panel` и на телефоне — без сетки. Пьедестал в `icpc`
  стоит по месту, подпись под именем — «решено · штраф». Медали, цвета
  участников, своя строка — как сейчас.
- Клетки: `solved` — фон `good-wash`, текст `good`, сверху «+» или «+N»
  (номер попытки минус один, если больше единицы), снизу минута; `first` —
  сплошная заливка `good` и текст цвета фона; `failed` — `bad-wash`/`bad`,
  «−N»; `pending` — `warn-wash`/`warn`, «?» и число; `untried` — пусто. Клетка
  имеет доступное имя: буква вопроса и состояние словами. Цвет никогда не
  единственный носитель смысла.
- Живая таблица организатора (`staff-standings.tsx`) показывает те же колонки
  и сетку.
- Токены: если нужны новые пары (например, текст цвета фона на `good`) — в
  `contrast.mjs`. `docs/design/SPEC.md` раздел 3.5 получает правило клеток
  ICPC.
- Тесты компонентов: сетка на `page`, её нет на `panel`; каждое состояние
  клетки с доступным именем; «первый решивший»; колонки штрафа. Затем
  `make front-check`.
