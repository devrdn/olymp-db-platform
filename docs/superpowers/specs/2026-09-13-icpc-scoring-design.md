# Режим оценки ICPC

Дата: 2026-09-13. Статус: согласовано, реализуется по плану
`docs/superpowers/plans/2026-09-13-icpc-scoring.md`.

## Задача

Третий режим оценки олимпиады рядом с «баллами» (`points`) и «первым
решившим» (`winner`): как на ICPC, где место решают число решённых вопросов и
время, за которое они решены.

## Принятые решения

Зафиксированы в обсуждении, дальше не пересматриваются.

1. **Баллов у вопроса в этом режиме нет.** Место решает число решённых
   вопросов, при равенстве — штрафное время. Поле баллов и процентный штраф
   вопроса в данных остаются (режим до старта можно вернуть), но в редакторе
   неактивны, участнику не показываются, а `submissions.points_awarded` и
   `registrations.total_score` получают 0.
2. **Штраф за неверную попытку настраивается на олимпиаде:** минуты, 0…240,
   по умолчанию 20. После старта олимпиады не меняется, как и сам режим.
3. **Вопрос с вариантами ответа требует лимита попыток меньше числа
   вариантов**, иначе ответ перебирается за штраф. Отказ гейта публикации.
4. **Замороженная ICPC-таблица показывает «ожидающие» попытки:** в клетке
   вопроса — число попыток после заморозки, без их результата. Это
   единственное осознанное ослабление правила «после заморозки с сервера не
   уходит ничего», и только для режима `icpc`.

## Расчёт

Отсечка и состояния таблицы — те же, что у лидерборда
(`2026-09-13-leaderboard-design.md`): `live` считается до «сейчас», `frozen` —
до `freeze_at`, `final` — до «сейчас».

По каждой паре «регистрация × видимый вопрос», по ответам до отсечки:

- **Решён**, если есть верный ответ. Первый верный — момент решения.
- **Неверные до решения** — число неверных попыток раньше первого верного.
- **Минута решения** — `floor((момент решения − старт) / 60 с)`. Старт: при
  общем окне `contests.starts_at`, при индивидуальном таймере
  `registrations.started_at`.
- **Штраф вопроса** — минута решения + `icpc_penalty_min` × неверные до решения.
  У нерешённого вопроса штрафа нет.

По регистрации: **решено** — число решённых вопросов, **штрафное время** —
сумма штрафов решённых, **последнее решение** — самый поздний момент решения.

**Порядок:** больше решённых выше; при равенстве меньше штрафного времени;
совпали оба — место общее (1, 1, 3). Внутри общего места строки идут по
последнему решению, затем по идентификатору регистрации — только ради
стабильного порядка.

**Первый решивший вопрос:** регистрация с самым ранним моментом решения этого
вопроса среди не дисквалифицированных, по ответам до отсечки. Во время
заморозки отметка ставится только по ответам до заморозки.

**Скрытые вопросы** (`is_visible = false`) в расчёт и в сетку не входят.

## Клетки сетки

У каждой строки — клетка на каждый видимый вопрос, в порядке `ord`. Вопрос
назван буквой (A, B, C…) по позиции среди видимых, никогда не идентификатором.

| Состояние | Когда | Что несёт клетка |
|---|---|---|
| `solved` | решён до отсечки | попытка, с которой решён; минута решения; признак «первый решивший» |
| `failed` | только неверные попытки до отсечки | число неверных попыток |
| `pending` | таблица заморожена, вопрос не решён до заморозки, и после заморозки были попытки | число попыток после заморозки (и сколько неверных было до заморозки) |
| `untried` | попыток до отсечки нет и `pending` не применим | ничего |

**Что уходит в `pending`:** только число попыток, отправленных в
`[freeze_at, now)`. Ни их верность, ни минуты, ни изменение «решено» и
штрафного времени. Регистрации после заморозки в таблице по-прежнему нет.
Живая таблица организатора `pending` не показывает: она считается до «сейчас»
и видит результат.

## Настройки, API и интерфейс

- **Схема:** `contests.scoring` принимает `icpc`; новая колонка
  `contests.icpc_penalty_min smallint NOT NULL DEFAULT 20` с проверкой 0…240.
- **API олимпиады** читает и пишет `icpc_penalty_min`; пакет олимпиады его
  переносит; сводка олимпиады для участника (`ContestSummary`) получает
  `scoring` и `icpc_penalty_min`, чтобы экран игры знал режим.
- **Ответ таблицы** в режиме `icpc` получает список букв вопросов, а строка —
  `penalty` (минуты) и `cells`. Для `points` и `winner` ответ не меняется.
- **Настройки:** в блоке «Как устроено» режим «ICPC» и поле штрафа в минутах,
  видимое только в этом режиме.
- **Редактор вопроса:** в ICPC-режиме баллы и процентный штраф неактивны с
  подписью «не используются в режиме ICPC».
- **Экран игры:** баллы вопроса не показываются; под списком вопросов —
  «+{n} мин за неверную попытку по решённому вопросу»; вердикт верного ответа
  без баллов.
- **Участники в админке:** колонка суммы баллов в ICPC-режиме не показывается.
- **Таблица:** колонки «место, участник, решено, штраф»; сетка — на публичной
  странице и у организатора, на широком экране. Во вкладке игры и на телефоне
  сетки нет. Цвета клеток: решено — зелёный, первый решивший — сплошной
  зелёный, неверные — красный, ожидает — жёлтый. Раздел 3.5 спеки дизайна
  получает правило клеток.

## Что не входит

- «Ожидающие» в режимах `points` и `winner`.
- Разные штрафы для разных вопросов.
- Несколько задач в олимпиаде (отложено, `2026-09-13-contest-tasks-design.md`).
