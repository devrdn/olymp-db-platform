# Рабочее место участника: заметки, вкладки SQL, просмотр журнала, сворачиваемые панели

Четыре улучшения экрана `/contests/{id}/play`. Все они про то, чтобы участнику
было удобно работать два-три часа подряд и ничего не терять при перезагрузке.

## 1. Где хранить: на сервере

Заметки и вкладки SQL хранятся **в основной базе, привязанными к регистрации
участника** (`registration_id`). Браузерное хранилище используется только как
черновик на время, пока правка ещё не дошла до сервера.

Почему сервер, а не `localStorage`:

- олимпиада идёт в компьютерных классах: профили браузера часто стираются при
  выходе, студента могут пересадить за другой компьютер, браузер может упасть.
  Данные в `localStorage` в этих случаях пропадают, а с сервера вернутся при
  следующем входе с любого устройства;
- данные принадлежат именно этой олимпиаде: регистрация удаляется, и они
  удаляются вместе с ней (`ON DELETE CASCADE`), без отдельной уборки;
- приватное окно или заблокированное хранилище не ломают функцию.

Черновик в `localStorage` (ключ по олимпиаде и вкладке) нужен для одного случая:
студент набрал текст и сразу перезагрузил страницу, а запрос сохранения не
успел уйти или не дошёл. Если черновик новее того, что пришло с сервера, экран
показывает черновик и сразу сохраняет его. После успешного сохранения
черновик удаляется.

Раскладка экрана (ширины колонок, какие панели свёрнуты) — это настройка
отображения конкретного компьютера. Она остаётся в `localStorage`, как ширины
колонок сейчас.

Преподаватели заметки и вкладки участника не видят: API для них нет. Это
личное рабочее пространство студента.

## 2. Автосохранение без кнопки

Одна общая для заметок и вкладок логика на клиенте (хук `useAutosave`):

- сохранение уходит через **1,5 с после последней правки**, но не реже чем
  раз в **10 с** при непрерывном наборе;
- немедленно — когда вкладка браузера скрывается (`visibilitychange`), при
  `pagehide` и при потере фокуса редактором. На `pagehide` запрос уходит с
  `keepalive: true` напрямую в `/api/v1/...` (как ссылка на CSV-журнал), потому
  что server action при закрытии страницы не отработает;
- текст не отправляется, если он совпадает с последним сохранённым;
- одновременно в полёте не больше одного запроса на документ; правки,
  сделанные во время запроса, уходят следующим запросом после его ответа;
- рядом виден статус: «Сохранено», «Сохраняется…», «Не сохранено — повторим».
  Неудачное сохранение повторяется с нарастающей паузой (2, 4, 8… до 30 с);
  текст в это время лежит в черновике.

На сервере запись — один `INSERT … ON CONFLICT DO UPDATE`. Действует правило
«последняя запись побеждает»: у одного студента два окна одновременно — редкий
случай, и сложная синхронизация ради него не нужна.

## 3. Ограничения (CLAUDE.md, правила 2, 5 и 13)

| Что | Предел |
|---|---|
| Текст заметок | 20 000 символов |
| Число вкладок SQL у участника | 10 |
| Название вкладки | 1–40 символов, без управляющих символов |
| Текст вкладки | `sqlpolicy.MaxQueryBytes` (64 КиБ), как у запроса |
| Частота записей | 60 в минуту на учётную запись участника, общий счётчик для заметок и вкладок; отказы тоже считаются |

Сверх частоты сервер отвечает 429 `workspace_too_often`, и клиент повторит
позже. При обычном наборе с паузой 1,5 с получается не больше 40 записей в
минуту даже при непрерывной печати.

Счётчик частоты ведётся по учётной записи участника, а не по регистрации:
учётная запись — единственный ключ, который известен до поиска участника и
олимпиады в базе, а ограничивать частоту нужно до этой работы (правило 13).
Ключ так же ограничен (один на учётную запись), а общий счётчик для двух
олимпиад одновременно — не случай олимпиады. Это отдельный бюджет: общий
бюджет чтения, который тратит консоль SQL, автосохранение не расходует, иначе
непрерывный набор отнимал бы у участника его запросы.

Читать и писать можно, только пока олимпиада допускает участника (тот же
`Access`, что и у `/play/story`). Когда олимпиада для него закончилась, все
маршруты рабочего места отвечают так же, как остальные маршруты `/play`:
409 `contest_not_running` или `contest_finished`. Режима «только чтение» нет:
экран `/play` после окончания всё равно недоступен.

## 4. API

Все пути под `/contests/{id}/play/`, аутентификация и проверка доступа те же,
что у остальных маршрутов участника (`ParticipantHandler.admit`).

Имена полей в запросах и ответах — в snake_case, как во всём API.

- `GET  /play/workspace` → `{ notes: {body, updated_at}, tabs: [{id, title, body, position, updated_at}] }`.
  `notes.updated_at` равно `null`, пока заметки ни разу не сохранялись.
  Если у участника ещё нет ни одной вкладки, сервер создаёт первую («Запрос 1»
  / «Query 1» / «Interogare 1» по языку запроса), поэтому у экрана всегда есть
  хотя бы одна.
- `PUT  /play/notes` `{body}` → `{updated_at}`.
- `POST /play/tabs` `{title?}` → созданная вкладка; без названия тело —
  пустой объект `{}`. На одиннадцатой — 409 `workspace_tab_limit`.
- `PATCH /play/tabs/{tabId}` `{title?, body?}` → `{updated_at}`; 404 для чужой
  или несуществующей вкладки (ответ не различает эти случаи).
- `DELETE /play/tabs/{tabId}` → 204; последнюю вкладку удалить нельзя
  (409 `workspace_last_tab`).
- `PUT /play/tabs/order` `{ids: [...]}`: порядок вкладок после перетаскивания.
  Список должен совпадать с набором вкладок участника.

Каждый отказ объявлен сентинелом, сопоставлен в `fail`, покрыт тестом
обработчика, код попадает в `docs/api/error-codes.json`, тексты есть на en/ru/ro.

Хранение — миграция `000032_play_workspace`:

```sql
CREATE TABLE participant_notes (
    registration_id uuid PRIMARY KEY REFERENCES registrations ON DELETE CASCADE,
    body            text NOT NULL,
    updated_at      timestamptz NOT NULL DEFAULT now()
);
CREATE TABLE participant_sql_tabs (
    id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    registration_id uuid NOT NULL REFERENCES registrations ON DELETE CASCADE,
    position        int  NOT NULL,
    title           text NOT NULL,
    body            text NOT NULL DEFAULT '',
    updated_at      timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX participant_sql_tabs_registration_idx ON participant_sql_tabs (registration_id, position);
```

## 5. Вкладки в SQL-редакторе

- Полоса вкладок над редактором, как в VS Code: название, крестик закрытия и
  «+» в конце полосы. Двойной щелчок по названию или F2 переименовывает
  вкладку: Enter сохраняет, Esc отменяет. Порядок меняется перетаскиванием.
  С клавиатуры вкладки доступны как `tablist`, стрелки переключают.
- Закрыть вкладку с текстом можно только после подтверждения; пустая
  закрывается сразу.
- Кнопка «Выполнить» и ⌘↵ запускают **текст активной вкладки**. Результат
  относится к последнему запуску, из какой бы вкладки он ни был: в заголовке
  результата указано название вкладки.
- У каждой вкладки свой документ CodeMirror (`EditorState`). Переключение
  меняет состояние одного `EditorView`: история отмены и положение курсора
  у каждой вкладки свои, и React при наборе текста по-прежнему ничего не
  перерисовывает.
- Какая вкладка активна, запоминается в `localStorage`: это настройка экрана,
  а не содержимое.
- Если запись отклонена, потому что олимпиада закончилась (`contest_not_running`
  или `contest_finished`), клиент прекращает автосохранение, оставляет
  черновик в `localStorage` и показывает, что олимпиада завершена.

## 6. Заметки

Третья вкладка боковой панели, «Заметки»: порядок вкладок — «История»,
«Вопросы», «Заметки», «Таблица». Это простое многострочное поле: без
Markdown, с автосохранением и статусом под полем. Рядом со статусом —
счётчик символов, который появляется при приближении к пределу (от 18 000).

Если сохранение заметок отклонено, потому что олимпиада закончилась, клиент
прекращает автосохранение, оставляет черновик в `localStorage` и показывает,
что олимпиада завершена.

## 7. Полный просмотр записи журнала запросов

- Щелчок по строке журнала (или Enter на ней: строки фокусируются) открывает
  **панель подробностей** под таблицей внутри той же вкладки. Строка
  подсвечивается как выбранная.
- В панели: полный текст запроса (только для чтения, моноширинный, с
  подсветкой SQL и переносом строк), статус, текст ошибки целиком,
  длительность, число строк, время. Кнопки: «Открыть в новой вкладке» (текст
  копируется в новую вкладку редактора, если вкладок меньше 10), «Копировать»
  и «Закрыть» (или Esc).
- Граница между таблицей и панелью перетаскивается по вертикали, с
  клавиатуры — стрелками, как существующие `PaneHandle`. Высота запоминается.
- Сейчас текст в журнале обрезается до 1000 символов (`MaxHistorySQLChars`).
  Для полной версии в ответ `/play/log` добавляется `id` записи и новый маршрут
  `GET /play/log/{entryId}`. Он возвращает одну запись целиком (не больше
  64 КиБ, как сам запрос) и только если она принадлежит этому участнику;
  иначе 404. Если текст не был обрезан, панель обходится без этого запроса.
- Граница между редактором и нижней панелью (результат/журнал) тоже
  перетаскивается по вертикали. Сейчас доли фиксированы (11:9); размер
  запоминается.

## 8. Сворачиваемые панели, как в VS Code

- Три панели можно свернуть: схема (слева), боковая (история, вопросы,
  заметки, таблица — справа, в этом порядке) и нижняя (результат и журнал).
- Переключатели — иконки в правой части шапки экрана с `aria-pressed` и
  подсказкой. Сочетания клавиш как в VS Code: Ctrl/⌘+B — левая, Ctrl/⌘+Alt+B —
  правая, Ctrl/⌘+J — нижняя. Они работают и когда фокус в редакторе.
- Свёрнутая колонка убирается из сетки вместе с разделителем, и редактор
  занимает освободившееся место. Если свернуть всё, на экране остаются
  только вкладки и редактор.
- Когда запрос выполнен, а нижняя панель свёрнута, она раскрывается сама:
  участник должен увидеть результат (как сейчас переключается вкладка
  «Результат»).
- Состояние хранится в `localStorage` по олимпиаде, рядом с ширинами колонок.
- На узком экране (< 760px) панели и так идут одна под другой. Переключатели
  там тоже работают и прячут соответствующие секции.

## 9. Проверка

- Бэкенд: тесты сервиса (пределы, частота, последняя вкладка,
  чужая вкладка), репозитория (`make test-db`) и обработчиков (коды 4xx).
- Фронтенд: vitest для `useAutosave` (задержка, максимальное ожидание,
  отсутствие дублей, повтор, черновик, отправка при `pagehide`), для полосы
  вкладок, панели подробностей журнала и переключателей панелей.
- Вручную, в браузере: 1440, 1024 (планшет), 768 и 375 px. Перезагрузка
  страницы не теряет ни заметок, ни вкладок. Если свернуть все панели,
  остаётся только редактор.
